## 2. Concept & Purpose

stox junior teaches kids how the stock market works through simulated trading with **fictional company names** mapped to real ticker behavior. Real tickers (AAPL, NVDA, etc.) are used internally as price seeds, but users only ever see playful aliases — keeping the experience approachable and consequence-free for younger audiences while still reflecting the underlying volatility and momentum patterns of real stocks.

| Real Ticker | Display Symbol | Display Name | Sector |
|---|---|---|---|
| AAPL | PEA | Pear | Big Tech |
| NVDA | NMV | Nmovia | Chip Makers |
| TSLA | EIN | Einstein | Cars & Energy |
| GOOG | GEG | Geggol | Big Tech |
| META | ATE | Atem Systems | Big Tech |
| AMZN | BRZ | Bravozon | Shopping |
| MSFT | MDS | Macrodense | Big Tech |
| AMD | SMD | Strong Mini Devices | Chip Makers |
| COIN | DST | Dollarstand | Money & Crypto |
| RBLX | PLY | Playbit | Gaming |

Stocks are grouped into 6 sectors — **Big Tech, Chip Makers, Shopping, Cars & Energy, Money & Crypto, Gaming** — which affects how they are browsed in the Market tab, how daily challenges are scoped, and how achievement tracking classifies each trade.

The app uses no real financial data feeds. Every price is generated algorithmically on-device, meaning it works offline and costs nothing to run at scale. Despite being fully synthetic, the prices exhibit realistic behaviors: momentum, mean-reversion tendencies, occasional shocks, and long-term compounding drift.

## 3. Architecture Overview

### App Entry Point

The launch sequence is: `StoxApp` → `RootView` → auth-state switch → `MainDashboard`. `RootView` watches an `AuthState` enum and routes between the welcome/login flow and the main dashboard depending on whether a valid session exists in `UserDefaults`.

### State Management

All application state lives in a single `@ObservableObject` class — `AppState` — which is injected at the root and consumed anywhere in the view tree via `@EnvironmentObject`. To keep the file manageable, `AppState` is split into seven Swift extensions:

| Extension | Responsibility |
|---|---|
| `AppState` (core) | Published properties, market refresh loop, net worth calculation |
| `+Auth` | Login, account creation, logout, session restore |
| `+Portfolio` | Buy/sell logic, cost basis tracking, split handling |
| `+Challenge` | Daily challenge evaluation, event tracking, claim logic |
| `+Achievements` | Achievement progress, tier claiming, streak tracking |
| `+Persistence` | Debounced Supabase saves, net worth snapshots, back-fill |
| `+Settings` | Appearance, sound, cellular, avatar, reset portfolio |

### Concurrency Model

All UI state mutations are confined to `@MainActor`. `AccountService` is declared as a Swift `actor`, which the compiler enforces as thread-safe — no locks or `DispatchQueue` needed. All networking uses `async/await`; there is no Combine in the codebase.

### Data Model

`UserAccount` is a plain `Codable` struct that maps 1:1 to a Supabase row. Sub-state that changes frequently (challenge progress, achievements, settings) is stored as nested JSON strings in dedicated columns (`daily_challenge_json`, `achievements_json`, `settings_json`). This approach allows the schema to evolve without database migrations — new fields can be added to the Swift structs and they simply default on decode.

### Monetary Precision

All balances are stored as **integer cents** (e.g., `cashBalance: Int`). This eliminates floating-point rounding drift that would otherwise compound across dozens of trades. Display formatting divides by 100 only at the point of rendering.

## 4. Authentication & Persistence

### Auth Flow

```
Welcome → Login / Create Account → (new users) Privacy Consent → MainDashboard
               ↘ Forgot Password ↗
```

- **Session persistence:** On successful login, the username is written to `UserDefaults`. On next launch, the app attempts to re-fetch the full account from Supabase using that username. If the fetch fails (network error, deleted account), the user is returned to the welcome screen cleanly.
- **Password security:** Passwords are hashed client-side with **SHA-256** via Apple's `CryptoKit` framework before being sent to Supabase. The server stores only the hash — plaintext passwords never leave the device.
- **Rate limiting:** `LoginRateLimiter` tracks failed attempts and enforces a lockout window to prevent brute-force attacks.
- **Account recovery:** Users can optionally link a "keycode" (typically an email address, but any string) stored inside their `settingsJSON`. The password reset flow searches all accounts for a matching keycode and returns the associated username, then allows a new password to be set.
- **New user consent:** First-time users are shown a Privacy Policy consent screen before reaching the dashboard. This is gated on a field in `UserAccount` so it only appears once.

### Persistence Strategy

Saves are **debounced** using a `pendingSaveTask`: every state-changing event (trade, achievement claim, setting change) cancels any in-flight save and schedules a new one 0.8 seconds later. This prevents rapid-fire writes from hammering Supabase during quick sequences like buying several stocks in a row.

**Net worth snapshots** are taken at two moments:
1. On every buy or sell (immediate)
2. Every hour via a background `Task` loop that fires while the app is in the foreground

When the app returns to the foreground (`scenePhase == .active`), a `catchUpSnapshots()` call back-fills any hours that were missed while the app was closed. This ensures the portfolio history chart always shows a continuous line even for users who only open the app once a day.

## 5. Stock & Price Engine

This is the most technically complex part of the app. All prices are generated algorithmically — there are no calls to any financial data provider. Despite this, prices exhibit realistic patterns including momentum, volatility scaling, occasional news shocks, and long-term compounding drift.

### Seeded Randomness: LCG + Box-Muller

The foundation of the entire price engine is `seededDailyReturn(ticker:dateString:)`. It works in two stages:

**Stage 1 — Linear Congruential Generator (LCG):** The ticker symbol and date string are concatenated and hashed into a `UInt64` seed using a polynomial rolling hash. The seed is then run through the standard Knuth 64-bit LCG twice:

```
state = state × 6364136223846793005 + 1442695040888963407
```

This produces two pseudo-random integers that look statistically random but are 100% deterministic — the same ticker and date always produce the same two numbers.

**Stage 2 — Box-Muller Transform:** The two LCG outputs are converted into a normally-distributed return using the Box-Muller formula:

```
return = sqrt(-2 × log(u1)) × cos(2π × u2) × 0.022 + 0.0012
```

This gives a return drawn from a normal distribution with:
- **Volatility:** 2.2% per day (~35% annualised) — enough to produce visible daily swings
- **Drift:** +0.12% per day (~+31% annualised) — a gentle upward bias so portfolios feel rewarding over time

Because the seed is derived from `ticker + date`, every user running the app on the same calendar day sees the **same price direction** for every stock. The simulated market is genuinely shared.

### Compounding from the Price Epoch

Every stock's price history begins from `priceEpoch = "2025-01-01"`. Starting from each stock's fixed base price on that date, the app runs a day-by-day compounding loop up to today:

```
price(day N) = price(day N-1) × (1 + seededDailyReturn(ticker, day N))
```

This means today's price reflects ~500+ days of compounded seeded returns, giving stocks genuine long-term drift and making price levels meaningfully different from their starting values.

### Stock Splits

When the compounded price of any stock crosses **$500**, a 2:1 split fires automatically: the price is halved and a `splitMultiplier` counter doubles. The app detects split events on market refresh and automatically adjusts a user's share count and average cost basis to match, so their portfolio value is preserved through the split.

### Five Price Layers

The raw compounded price is the foundation, but five additional components are stacked on top to make prices feel alive:

| Layer | Behavior |
|---|---|
| **Momentum (5-day)** | Averages the seeded returns of the past 5 days. A stock that has consistently risen gets an amplified upward push (×2.5 of the average return), making trending stocks feel genuinely driven by momentum rather than random walk. |
| **Opening Amplifier** | A seeded roll in `[-10, 10]` is multiplied by a `volatilityMultiplier` (`200 / basePrice`, capped 0.5–5.0). Cheaper stocks swing dramatically on open; large-cap equivalents barely move. |
| **News Shock** | A 10% chance (seeded per ticker+date) of a sudden ±6% jolt — simulating an unexpected earnings report or market event. Stable across refreshes so all users experience the same "news" on the same day. |
| **Intraday Tick** | A stable ±1.5% nudge seeded with the suffix `"noon"`, independent of the daily return seed. Prevents price-fishing — users can't keep refreshing to hunt for a lucky spike. |
| **Display Tick** | The only truly random component: a small random wiggle (capped at ±$4) added fresh on each refresh so the price visibly changes. This is purely cosmetic. |

### 90-Day Analysis Chart

`fetchPriceAnalysis()` builds a 90-day closing-price series by running the same compounding loop for each of the past 90 calendar days, then rescaling the entire series so its final point matches today's compounded price exactly. This keeps the chart anchored to a realistic endpoint while showing genuine historical drift. The result is cached to `UserDefaults` once per calendar day so it is only computed once regardless of how many times the user opens the analysis view.

`PriceAnalyzer` then runs five metrics on those 90 prices: 20-day SMA, OLS regression slope, annualised volatility, local maxima/minima detection, and a trend signal (Bullish / Neutral / Bearish).

## 6. Core Trading Mechanics

### Buying

The `BuySheet` presents a stepper (−, share count, +, Max) alongside a live cost summary and remaining-cash preview. Tapping Max fills the stepper with the maximum whole shares affordable at the current price. On confirm:

- Cash is debited in integer cents to avoid rounding errors.
- The **weighted average cost basis** is recalculated: `(existingShares × existingCost + newShares × currentPrice) / totalShares`. This is the standard brokerage method and means the average cost stays accurate across multiple buys at different prices.
- Achievement counters (volatile shares, momentum shares, floor shares, max shares held) update immediately.
- The active daily challenge is evaluated to see if the buy satisfies it.

### Selling

Swipe left on any owned stock in the Portfolio tab to reveal the `SellSheet`. The stepper lets the user choose how many shares to sell (up to the full position). On confirm:

- The trade is checked against the average cost basis to determine profit or loss — this drives the `profitSells` and `lossSells` achievement counters.
- If remaining shares drop to zero, the position is removed entirely and the `holdingStartDate` for that ticker is cleared (resetting Loyalty achievement tracking).
- The active daily challenge is evaluated (e.g., "sell a rising stock").

### Quick Buy

Quick Buy is an automated one-tap purchase tool in the Portfolio tab. The user enters a dollar budget and selects one of three strategies:

- **Passive** — Ranks stocks by `slopeRate × 3 − |changePercent|`. Favors stocks with steady upward slope and low intraday volatility — a conservative long-term approach.
- **Momentum** — Ranks by `changePercent × 0.5 + slopeRate × 0.5 + trendBonus` where `trendBonus` rewards stocks with a Bullish trend signal. Favors stocks already moving strongly upward.
- **Value** — Ranks by `−(price − floor) / price`. Favors stocks trading closest to their historical floor support — a "buy the dip" approach.

The algorithm iterates through candidates in rank order, buying up to 3 shares of each qualifying stock, then dumps any remaining budget into the top-ranked pick. Each use increments the `quickBuyCount` achievement counter and is tracked against the daily challenge.

### Sell All

A confirmation alert in the Portfolio tab sells every open position at current market prices in a single action. Useful for resetting strategy or responding to a market-wide downturn.

## 7. User Interface

### Navigation

`MainDashboard` is a **custom swipe-pager** — not a `TabView`. Three pages sit in an `HStack` and are driven by an `@State` page index. A `DragGesture` overlay handles swipe navigation with:
- A rubber-band resistance effect when dragging past the first or last page
- **Directional bias** so that predominantly vertical drags pass through to the scroll views inside each tab instead of triggering a page switch

Tab buttons at the bottom are purely decorative indicators; all navigation happens via swipe.

### Persistent Top Bar

Visible on all three tabs:
- **Left:** Info button → `InfoView` sheet with app explanation and disclaimers
- **Center:** 🔥 login streak count + 💎 gem count
- **Right:** 🏆 achievements button (red dot badge appears when any tier is claimable) + profile avatar button

### Home Tab

The landing screen after login. Shows:
- Personalised welcome greeting with current cash balance
- **Daily Challenge card** with a progress bar and a claim button that activates when the target is met
- **Mini net-worth chart** — a SwiftUI Charts area+line chart using CatmullRom curve interpolation for smooth rendering. Tapping it navigates to the Portfolio tab.
- **Market highlights** row: Top Gainer, Top Loser, and Steadiest stock for the day — each tappable to open `StockAnalysisView`

### Market Tab

- Stocks are grouped into **collapsible sector sections**, each with an SF Symbol icon. Sections can be individually expanded/collapsed.
- Each stock row is a `SwipeRevealCard`: swiping right reveals a quick-buy button that opens `BuySheet`; tapping the row navigates to `StockAnalysisView`.
- **Pull-to-refresh** triggers `refreshMarket()`, which regenerates all stock prices (including the display tick) and upserts the results to Supabase so other users see the update.

### Portfolio Tab

- Owned stock list with swipe-left-to-sell via `SellSheet`
- **Sell All** button with confirmation alert
- **Portfolio Insight Card** — an AI-style narrative card that summarises the current portfolio composition and suggests actions based on diversification and trend signals
- **Quick Buy card** — budget input + strategy selector + execute button
- **Portfolio History chart** — net worth over time plotted as a SwiftUI Charts area chart

### Stock Analysis View

A full-screen deep-dive per stock showing:
- **90-day interactive price chart** with a draggable cursor (using Swift Charts' `chartOverlay` + `ChartProxy`) that snaps to each day and displays the exact closing price and 20-day SMA value
- A dashed rolling-SMA line overlaid on the price area
- Trend signal badge (Bullish / Neutral / Bearish)
- Quantitative stats: volatility, slope, SMA, price-vs-SMA spread
- Local maxima and minima markers showing resistance and support levels
- Day high/low range and floor (prior day's close)
- Sector and stock description

### Overlays & Animations

- **Gem burst** — when gems are earned, a pill pops in at centre screen and floats upward with a spring animation
- **Streak popup** — a full-screen orange/yellow gradient banner with the current streak count, shown once per day when the streak advances to 2 or higher
- **Tutorial overlay** — a multi-step guided walkthrough shown automatically on first login, explaining each part of the UI

### Color System

`AppColors` defines a set of named semantic tokens so the entire app palette can be changed in one place and responds correctly to light/dark mode:

`background`, `surface`, `surfaceSecondary`, `accent`, `gain`, `loss`, `highlight`, `textPrimary`, `textSecondary`, `textTertiary`, `cardBorder`, `divider`, `inputBackground`, `sheetBackground`, `warning`

## 8. Gamification Systems

### Gems 💎

Gems are the in-app currency. They are earned through engagement and spent exclusively on cosmetic avatar unlocks.

**Earning gems:**
- Daily challenge completion: **+5 gems**
- Login streak of 2 or more consecutive days: **+1 gem per day**
- Achievement tier claims: **+10 / +30 / +60 / +100 / +200 gems** (Amateur through Platinum)

### Daily Challenges

One challenge is active per calendar day, selected deterministically by the formula:

```
(year × 400 + month × 31 + day) % 10
```

This means everyone gets the same challenge on the same day. There are 10 challenge types:

| # | Challenge | Tracking Method |
|---|---|---|
| 0 | Sell a rising stock | Triggered on sell if `changePercent > 0` |
| 1 | Buy 5 tech sector shares | Counts shares bought in Big Tech or Chip Makers |
| 2 | Use Quick Buy with ≥ $1,000 budget | Single threshold check on Quick Buy execute |
| 3 | Open advanced analysis for 3 different stocks | Deduplicates by ticker — same stock doesn't count twice |
| 4 | Bring cash up to $4,000 | Continuously re-evaluated against current `cashBalance` |
| 5 | Spend $2,000 on stocks today | Accumulates `totalSpentToday` across all buys |
| 6 | Buy from Gaming or Shopping sector | Single qualifying purchase |
| 7 | Bring cash down to $6,000 | Continuously re-evaluated against current `cashBalance` |
| 8 | Grow net worth by 2% today | Compares `currentNetWorth` to `netWorthAtDayStart` |
| 9 | Use Quick Buy 3 times | Counts Quick Buy executions |

All dollar thresholds scale proportionally to the user's chosen starting balance, so the challenge is equally meaningful whether you started with $500 or $100,000.

### Achievements

12 achievement categories, each with 5 tiers that must be unlocked and claimed sequentially. Claiming a tier pays out gems and unlocks the next tier's target.

| Tier | Gem Reward |
|---|---|
| Amateur | +10 |
| Bronze | +30 |
| Silver | +60 |
| Gold | +100 |
| Platinum | +200 |

| Achievement | What It Tracks |
|---|---|
| **Diverse Portfolio** | Count of unique tickers ever owned across all time |
| **Investor** | Maximum shares held in a single stock simultaneously |
| **Gambler** | Shares bought in stocks with ±2% or higher daily volatility |
| **Intellectual** | Number of times the advanced stock analysis view was opened |
| **Spontaneous** | Total Quick Buy executions |
| **Safe Investor** | Shares bought in steady, low-volatility stocks |
| **Momentum Buyer** | Shares bought in stocks rising more than +2% on that day |
| **Bargainer** | Shares bought when the price is near the stock's historical floor |
| **Profit Taker** | Number of sells completed at a profit vs. average cost basis |
| **Loss Cutter** | Number of sells completed at a loss |
| **Market Addict** | App opens within a rolling time window — targets: 15 opens/5 days → 30/7 → 50/15 → 100/25 → 500/100 |
| **Loyalty** | Shares held continuously — targets: 3 shares/5 days → 10/15 → 15/30 → 30/100 → 50/250 |

Market Addict uses a rolling window (not a lifetime counter) — timestamps older than 100 days are pruned automatically. Loyalty checks whether any current position has been held continuously for the required number of days with enough shares, tracked via `holdingStartDates`.

A red dot badge on the achievements button in the top bar appears whenever any tier across any category becomes claimable.

### Login Streaks

`advanceStreakIfNewDay()` runs on every app open. It compares today's date key to yesterday's:
- **Match** → streak increments and longest streak updates if surpassed
- **Gap** → streak resets to 1
- **Same day** → no change (duplicate opens don't advance the streak)

Streak data (current, longest, last login date) is stored inside `achievementsJSON` and persists to Supabase with every save.

## 9. Settings & Personalization

Accessed by tapping the profile avatar button in the top bar. All settings persist to Supabase inside `settingsJSON`.

- **Appearance** — Light / Dark / System. Applies `preferredColorScheme` at the app root so every view responds correctly.
- **Sounds & Haptics** — Single toggle disabling both `HapticsManager` (taptic engine feedback on buy, sell, celebrate) and `SoundManager` (audio cues).
- **Block Cellular Data** — When enabled, `StockService` will only fetch when on Wi-Fi. Useful for users on limited data plans.
- **Account Recovery** — Lets the user link a keycode (any text, typically an email) to their account. Used by the Forgot Password flow to identify the account without storing an email at registration time.
- **Avatar Picker** — A tiered gallery of avatar images purchasable with gems. Owned avatars are stored in `settingsJSON`; the selected avatar appears in the profile button and on the profile screen.
- **Reset Portfolio** — Wipes all trades, gems, and achievements (login streak is preserved). User selects a new starting balance: $500 / $10,000 / $100,000 / $100,000,000. Challenge dollar thresholds scale proportionally to this value.
- **Log Out** — Clears the `UserDefaults` session and returns to the welcome screen.
- **Delete Account** — Permanently removes the account row from Supabase and returns to the welcome screen.

## 10. Services Layer

| Service | Type | Role |
|---|---|---|
| `AccountService` | `actor` | All Supabase REST calls — login, account creation, fetch, save, password recovery, delete |
| `MarketService` | `actor` | Reads and writes the shared `market_prices` Supabase table — upserts on refresh, fetches on launch |
| `StockService` | `struct` | Generates all synthetic stock prices; builds the 90-day compounded analysis histories |
| `PriceAnalyzer` | `struct` (static) | Pure math engine — SMA, OLS slope, volatility, local extrema, trend signal. Zero networking, zero side effects. |
| `HapticsManager` | `class` | Centralised taptic engine calls: click, buy, sell, celebrate |
| `SoundManager` | `class` | Plays purchase and celebration audio |
| `LoginRateLimiter` | `struct` | Tracks failed login attempts per session and enforces lockout periods |

`PriceAnalyzer` is intentionally stateless and pure — given the same `[Double]` array it always returns the same `PriceAnalysis`. This makes every formula independently testable with no mocking required.

The `MarketService` and `AccountService` are both Swift `actor`s, which means the compiler enforces that their internal state is never accessed concurrently. All calls into them are naturally `async` and integrate cleanly with the `await`-based call sites in `AppState`.
